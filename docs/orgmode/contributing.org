* Contributing

Changes come as pull requests to [[https://github.com/stackhands/eb-keep-logs][stackhands/eb-keep-logs]].
A change to behaviour changes the page that describes it in the same pull request.

** Record the change

Every change adds a news fragment, =changelog.d/+SLUG.TYPE.md=, with a short slug for the change and one of the types =towncrier.toml= configures:

| Type      | Section of the release notes |
|-----------+------------------------------|
| =feature= | Features                     |
| =bugfix=  | Fixes                        |
| =doc=     | Documentation                |
| =removal= | Removals                     |
| =misc=    | Miscellaneous                |

A fragment is one paragraph in the present tense that names the commands, options and files it is about in backticks, as the entries in the [[file:changelog.org][changelog]] do.
=towncrier build --draft --version 0.2.2= shows the release notes the fragments make, and fails on a fragment whose type is not configured.
The release commit gathers them into =CHANGELOG.md=; [[https://github.com/stackhands/eb-keep-logs/blob/main/RELEASING.md][RELEASING.md]] has the rest of a release.

** Run the tests

With Zig 0.17.1, from the top of the repository:

#+begin_src bash
zig build test
#+end_src

This runs the unit tests, the command-line suite =tests/test_eb_keep_logs.sh= against the binary, and =tests/differential.sh=, which runs the shell script and the binary on the same invocations.
=bash tests/test_eb_keep_logs.sh= runs the suite against the shell script.
A deliberate difference between the two has its row in =COMPAT.md=, which [[file:reference/compatibility.org][Compatibility]] shows, and its label in =tests/differential.sh=.

** The log corpus

=tests/fixtures/build-logs/= is the log tree of real EasyBuild 5.4.2 builds on top of EESSI 2025.06, laid out as eb-pipeline lays out its runs, =RUN/TARGET/NAME.stdout.log=, with what =eb-keep-logs failed= kept beside each failed build.
The builds of GNU hello 2.12.1 in =tests/corpus/cases/= fail as builds do: a checksum of another release, a patch made for an older version, a dependency nobody packaged, a configure that finds no working compiler, a compile error, an undefined reference, a failing test and a sanity check path that is not there; the last run builds it.
=eb-keep-logs rotate= compressed the first four runs.

The builds ran as =alice= on a host named =node1=, so the logs name no real user or host.
To make the tree again, mount EESSI's CernVM-FS repository, put =eb-keep-logs= on =PATH=, and run each case as a run of its own, in UTC as eb-pipeline names its runs:

#+begin_src bash
export TZ=UTC
for c in checksum patch missing-dep configure; do tests/corpus/run.sh sapphirerapids "$c"; done
EB_KEEP_LOGS_NOW=$(($(date +%s) + 86400)) eb-keep-logs rotate ~/build-logs --compress-after 1
for c in compile link; do tests/corpus/run.sh sapphirerapids "$c"; done
export STAMP=$(date +%Y%m%d_%H%M%S)
tests/corpus/run.sh sapphirerapids test sanity
tests/corpus/run.sh generic pass
unset STAMP
tests/corpus/run.sh sapphirerapids pass pass-13
tests/corpus/make-fixtures.sh ~/build-logs tests/fixtures/build-logs "$(command -v eb-keep-logs)"
#+end_src

=make-fixtures.sh= drops lines and never edits one.
Of each kept session log it keeps EasyBuild's warnings and errors and the records of its messages, steps and shell commands, without the output of the commands that succeeded or the middle of a failed command's output longer than 160 lines; EasyBuild's own copies of its logs stay out.

** Build the documentation

The documentation toolchain is pinned in =pixi.lock=: Emacs, Sphinx, lychee, and the tools that read the code.
With [[https://pixi.sh][pixi]] installed, from the top of the repository:

#+begin_src bash
pixi run -e docs docbld
#+end_src

The site is in =docs/build/html/=; open =docs/build/html/index.html=.
The build fails on any Sphinx warning, any cross-reference that does not resolve, any internal link or anchor that does not exist, and, outside the changelog, any name of a real site's machines or paths.
The first build needs the network, to fetch the other stackhands sites' inventories; later builds reuse them for 30 days.

External links are checked separately, as they need the network:

#+begin_src bash
pixi run -e docs linkcheck
#+end_src

=pixi run -e docs docdel= removes everything the build generated.

** Where things are

| Path                       | What it holds                                      |
|----------------------------+----------------------------------------------------|
| =docs/orgmode/=            | the pages, in Org: edit these                      |
| =docs/export.el=           | the Org to reStructuredText export                 |
| =docs/source/conf.py=      | the Sphinx configuration                           |
| =docs/source/_ext/=        | the Sphinx domain for Zig declarations             |
| =docs/tools/zig_api.zig=   | writes the Zig API pages from the doc comments     |
| =docs/tools/check_site.py= | checks internal links, anchors and forbidden names |
| =tests/corpus/=            | the builds the log corpus comes from               |
| =tests/fixtures/=          | the log corpus                                     |

The =.rst= files under =docs/source/= and everything under =docs/source/reference/api/= are generated and not committed.

** Write a page

A page belongs to exactly one quadrant: a tutorial teaches by doing, a how-to guide gets one task done, an explanation says why, and a reference page lists what there is.
Start from the skeleton for its quadrant in =docs-kit/skeletons/= of [[https://github.com/stackhands/.github][stackhands/.github]], add it to the =toctree= of the quadrant's =index.org=, and follow =docs-kit/STYLE.md= there.
Examples use the neutral example site (=example.org=, =/opt/site=, =/home/alice=), never a real one.

API documentation is written in the code, and the first sentence of each comment is the summary shown in lists.
In Zig it is a =///= comment above each =pub= declaration and a =//!= comment at the top of each file.
